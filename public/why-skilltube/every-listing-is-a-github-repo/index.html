Every listing lives in its own public GitHub repository

Ownership, history, licence and issues stay with the developer; SkillTube provides a discovery card and link.

2026-11-24
GitHubownership

SkillTube is a directory, not a code host. Every listing points to a public GitHub repository that belongs to the developer who signed in. That arrangement keeps the project's source, history and issue tracker in the place its maintainer already controls. A directory entry should help someone discover the project without creating a second, competing copy of it.

Keeping the repository as the source of truth matters when a project changes. Developers can use their normal GitHub workflow to improve instructions, fix bugs, add releases or change a licence. SkillTube's catalog checks repository availability and follows renames, but the repository remains the authoritative source for current files and project activity.

Each listing adds discovery information around that repository: a name, short and long descriptions, three topic tags and two sets of detail tags. Those fields are designed to make different AI resources easier to compare. They do not replace the README, source code, examples or licence in the repository. Visitors should read those materials before installing or using a project.

The same approach works for AI skills, MCP servers, datasets, databases, prompts, agents and other AI tools. Their contents differ, and each requires its own context. A listing can explain the basic purpose and give a visitor a route to the source; it cannot safely capture every technical detail or operational warning in a small card.

This boundary also limits what SkillTube promises. The directory does not guarantee that repository content is safe, available forever or compatible with a particular assistant. A developer controls their project and its licence. A visitor chooses whether to open, run or rely on it. Reports and moderation help respond to concerns, but they do not turn the directory into a code audit service.

When you find a promising listing, follow the link to GitHub. Check the owner, recent history, documentation, dependencies and licence. If you publish, list only a public repository you own and keep its description accurate. SkillTube's job is to make the route to that source clearer.

That separation is useful for maintainers too. They can correct a project in its original repository instead of asking a directory to update a second file copy. When a listing description becomes outdated, they can edit the directory fields, while installation instructions and release details remain with the project. This keeps the developer in control of the resource and gives visitors one place to verify its current source.
