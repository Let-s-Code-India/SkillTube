AI skills are the main focus of SkillTube, but useful AI work also includes infrastructure and supporting resources. An MCP server can expose tools or data to an assistant. A dataset can help with retrieval or evaluation. A database can store embeddings or application state. Prompts, agents, workflows and standalone tools can also be part of a practical system.

These projects differ, so a listing should explain the details that matter for its type. An MCP server can describe its transport, tools and configuration example. A dataset can state its size, format, source, licence and update policy. A database project can explain compatibility and setup. The long description has room for these notes without introducing a different backend schema.

The same listing fields and 3 + 9 + 27 tag structure apply. The selected resource type helps prefill a topic and show a useful description template, but it is not sent as a new server field. Search treats type words as regular tags and descriptions, so developers should choose relevant tags rather than relying on the type label alone.

Repositories should make important limitations easy to find. Data licences and provenance matter; servers may execute code or access local resources; agents may call tools; prompts can make claims that are not tested. SkillTube does not audit or certify these projects. Visitors should read the repository, inspect permissions and test in a safe environment before use.

Keeping each listing connected to a public GitHub repository leaves version history, issues and release files with the maintainer. A directory card makes discovery more consistent, but it cannot summarize every technical requirement or risk. The source repository remains the place to verify what is actually included.

If you build any of these resources, you can use SkillTube without changing where you host them. Describe what the project is, how to try it, what it requires, what its licence permits and where it has limits. Clear context helps people choose the right next step.

The category is not a promise of compatibility with every assistant or deployment. Explain versions, supported runtimes and external services where relevant, and state whether setup requires credentials or local permissions. For datasets, distinguish a sample from the full collection and describe update cadence. Accurate details make a listing more useful than a broad label, while the repository remains the place for complete technical instructions.
